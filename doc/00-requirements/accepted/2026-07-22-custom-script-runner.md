# 自定义脚本执行页面需求

## 文档状态

- 状态：已确认
- 确认日期：2026-07-22
- 功能分支：`codex/custom-script-runner`
- 页面名称：脚本执行

## 背景

当前应用主要提供 TortoiseGit 仓库操作。用户还需要在不同的本地目录中重复执行自定义脚本，例如 Python、批处理和 PowerShell 脚本。脚本本身由用户维护，应用负责保存入口配置、选择执行目录、启动进程并集中展示运行状态和输出。

## 目标

在左侧“功能导航”中新增“脚本执行”入口，为用户提供以下能力：

- 管理一组全局共享的自定义脚本按钮。
- 管理并快速切换最近使用的执行目录。
- 在页面当前执行目录下启动所选脚本。
- 允许多个脚本以及同一脚本的多个实例并行运行。
- 在应用页面内分别查看每个运行实例的状态和实时输出。
- 停止指定运行实例及其整个子进程树。

## 页面结构

“脚本执行”页面采用三段式布局：

1. 顶部为执行目录区域，包括当前目录下拉框、选择目录按钮和目录列表管理入口。
2. 中部为脚本按钮区域，包括脚本按钮、新建脚本入口和脚本管理入口。
3. 底部为运行实例区域，实例通过底部标签页切换；标签页上方显示详情、实时输出、终止和移除操作，并提供一键清除已结束记录。

切换到其他导航页面时，正在运行的脚本继续执行并持续收集输出。返回“脚本执行”页面后，可以继续查看原有运行实例。

## 执行目录

### 基本规则

- 执行目录是页面级状态，不与单个脚本绑定。
- 点击任意脚本按钮时，使用当时选中的执行目录作为该运行实例的工作目录。
- 执行目录允许选择任意存在的本地文件夹，不要求属于 Git 仓库。
- 执行目录与“仓库管理”页面的当前仓库相互独立。
- 脚本运行期间切换执行目录，只影响之后启动的新实例；已运行实例继续使用启动时的目录。

### 初始目录优先级

首次进入页面时，按以下顺序确定当前执行目录：

1. 上次选择且仍然有效的执行目录。
2. 当前仓库根目录。
3. 程序启动目录。

### 最近目录管理

执行目录列表参考现有仓库列表管理交互，支持：

- 从下拉框快速切换。
- 添加任意存在的文件夹。
- 修改显示名称，不修改真实路径。
- 手动调整顺序。
- 删除条目。
- 记住上次选择的目录。

目录不存在或暂时不可访问时，保留配置并标记为无效，不允许在该目录下启动新实例；用户可以修正或删除该条目。

## 脚本配置

### 配置字段

每个脚本配置至少包含：

- 稳定的唯一标识。
- 脚本名称。
- 脚本文件绝对路径。
- 脚本类型。
- 原始命令行参数文本，可为空。
- 内置图标标识。
- 显示顺序。

脚本配置全局共享，不随执行目录或仓库变化。

### 创建流程

- 用户可以通过文件选择器选择脚本，也可以手动输入绝对路径。
- 保存时必须校验脚本文件存在。
- 第一版只允许 `.py`、`.bat`、`.cmd` 和 `.ps1` 文件。
- 选择文件后，默认名称为不含扩展名的文件名。
- 创建界面提供默认名称和默认图标，用户可以修改名称、参数和图标。
- 脚本路径为必填项，命令行参数为可选项。
- 新脚本默认添加到脚本列表末尾。

### 管理能力

创建后支持：

- 修改名称、脚本路径、命令行参数和图标。
- 手动调整脚本按钮顺序。
- 删除脚本配置。

如果脚本文件后来被移动、删除或不可访问，按钮继续显示并标记“路径无效”，同时禁止执行；用户可以进入编辑界面修正路径或删除配置。

### 图标范围

第一版保留图标选择控件和稳定的图标标识字段，但只提供一个默认脚本图标。后续增加内置素材图时，已有配置不需要迁移。

## 脚本启动规则

第一版按扩展名选择启动方式：

| 类型 | 启动方式 | 说明 |
| --- | --- | --- |
| `.py` | 系统 `PATH` 中的 `python` | 找不到 Python 时创建“启动失败”实例并显示错误 |
| `.bat`、`.cmd` | `cmd.exe /c` | 在页面当前执行目录下运行 |
| `.ps1` | Windows PowerShell | 遵循系统当前执行策略，不使用 `ExecutionPolicy Bypass` |

所有类型都满足以下规则：

- 脚本文件使用配置中保存的绝对路径，应用不复制或修改原文件。
- 命令行参数按用户填写的原始文本传递。
- 第一版不提供参数变量、日期变量或工作目录占位符替换。
- 子进程继承应用当前环境变量。
- 不请求管理员权限，也不自动提升权限。
- 启动参数必须正确处理脚本路径和工作目录中的空格及特殊字符。

## 运行实例

### 并发规则

- 允许不同脚本并行运行。
- 允许同一个脚本同时启动多个运行实例。
- 每次点击脚本按钮都创建独立实例，并记录启动时的脚本配置快照和执行目录。
- 后续编辑脚本配置不影响已经启动的实例。

### 状态与信息

每个运行实例显示：

- 脚本名称。
- 运行状态。
- 启动时的执行目录。
- 开始时间。
- 结束时间或实时耗时。
- 进程退出码。

状态至少包括：

- 运行中。
- 正在终止：已收到用户终止请求，正在结束进程树。
- 成功：进程正常结束且退出码为 `0`。
- 失败：进程结束且退出码非 `0`。
- 已停止：用户主动终止。
- 启动失败：解释器、脚本或工作目录不可用，或者进程无法创建。

### 停止与退出

- 每个运行中的实例提供独立“停止”操作。
- 停止时终止该实例的整个进程树，包括脚本启动的子进程。
- 关闭应用时若仍有实例运行，弹出确认提示。
- 用户取消退出时不影响运行实例。
- 用户确认退出时终止全部运行实例及其子进程，然后关闭应用。

## 输出区域

- 标准输出和标准错误都重定向到应用页面内。
- 每个运行实例独立保存并展示自己的输出。
- 输出应在运行过程中持续更新，不能等待进程结束后一次性显示。
- 第一版不支持向脚本发送标准输入。
- 第一版不提供输出编码选项，按系统默认编码读取。
- 每个实例最多保留最新 `10,000` 行输出；超出后从最早内容开始丢弃。
- 运行实例和输出只保留在当前应用会话中，关闭程序后不持久化。
- 已结束实例支持单独移除。
- 支持一键清除全部已结束实例。
- 运行中的实例不能直接移除，必须先停止。

## 数据持久化

脚本配置、最近执行目录、显示顺序和上次选择的执行目录保存到：

```text
%LOCALAPPDATA%\TortoiseGitLauncher\
```

使用独立 JSON 配置，不修改现有 `recent-repos.json` 的格式。配置应包含版本字段，并满足以下兼容性要求：

- 单个坏条目不应导致整个配置无法读取。
- 缺少新增字段时使用明确默认值。
- 未识别的图标标识回退到默认脚本图标。
- 路径失效时保留条目，交由用户修正或删除。
- 写入失败不应导致应用崩溃，但必须给出可见错误提示。

## 行为边界

第一版不包含：

- 脚本标准输入交互。
- 运行输出和历史实例持久化。
- 输出编码选择。
- 参数模板或变量替换。
- 定时任务、计划执行或开机启动。
- 管理员权限提升。
- 脚本文件复制、编辑或版本管理。
- 用户导入自定义图片作为图标。
- Git 仓库与执行目录自动同步。
- 远程脚本或网络脚本执行。

## 验收标准

### 导航与目录

- 左侧导航出现“脚本执行”，可以在仓库管理页和脚本执行页之间切换。
- 可以选择任意存在的本地目录，并将其保存到最近目录列表。
- 最近目录支持重命名显示名、排序、删除和下拉切换。
- 重启应用后恢复上次有效的执行目录。
- 切换仓库不会改变脚本执行目录。

### 脚本配置

- 可以创建 `.py`、`.bat`、`.cmd` 和 `.ps1` 脚本配置。
- 创建时默认名称取文件名且不包含扩展名，并显示默认图标。
- 可以填写原始命令行参数。
- 可以编辑、排序和删除已有脚本。
- 重启应用后脚本按钮、顺序和配置保持不变。
- 脚本路径失效时按钮有明确标记且不能执行。

### 执行与并发

- `.py` 使用 `PATH` 中的 `python` 启动。
- `.bat` 和 `.cmd` 通过 `cmd.exe /c` 启动。
- `.ps1` 通过 Windows PowerShell 启动并遵循系统执行策略。
- 脚本的工作目录等于点击按钮时的页面当前执行目录。
- 同一脚本可以启动多个并行实例。
- 切换页面和切换执行目录不会中断已运行实例。

### 状态、输出与停止

- 每个实例独立显示状态、时间、耗时和退出码。
- 标准输出和标准错误在页面内实时显示。
- 退出码 `0` 显示成功，非 `0` 显示失败，用户终止显示已停止。
- 可以停止单个实例及其整个子进程树。
- 每个实例仅保留最新 `10,000` 行输出。
- 可以移除单个已结束实例并一键清除所有已结束实例。
- 关闭应用且仍有脚本运行时必须请求用户确认。

## 后续扩展预留

- 增加多套内置脚本图标。
- 增加输出编码选择。
- 增加参数变量和工作目录占位符。
- 增加标准输入交互。
- 增加运行历史持久化、搜索和导出。
